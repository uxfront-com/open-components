Let's start with how a combobox looks: its parts, one or several values, groups, icons, sizes, its states and the variables that restyle each part.

## Anatomy

::combobox-anatomy
1. **Field** — The root, a `<div>` that draws the border, the background and the focus ring, and holds the parts below.
2. **Leading icon** — Optional. An icon before the text, hidden from assistive technologies.
3. **Icon** — Optional. An icon for each option, shown in the panel, beside the picked option's label and in each tag, hidden from assistive technologies.
4. **Text** — The `<input>` people type in, which has the `combobox` role and shows the picked option's label.
5. **Toggle** — A `<button>` with the chevron, which opens and closes the panel and turns as it does. It's out of the tab order.
6. **Tag** — With `multiple`, one per value, with its own remove button, on a row under the text.
7. **Panel** — The floating listbox, with its own scroll boundary, in the top layer while it's open.
8. **Group label** — Optional. A heading for a group of options.
9. **Option** — One suggestion, with its hover, highlighted, selected and disabled states, and a check mark when it's picked.
10. **Separator** — Optional. A rule between options or groups.
11. **Create option** — With `creatable`, a last option that adds what people typed. In its place, the panel says "No results" when nothing matches.
::

The field is the root, as on the [Select](/docs/components/select/ui#anatomy), and the `<input>` fills its first row, under the icons, so it lines up with an [Input](/docs/components/input/ui#anatomy) of the same size. The panel, its options, its groups, its separators and the tags are the Select's, drawn by the same code with the same tokens, so the two components look the same wherever they meet. You can see the order of the parts in the [DOM contract](/docs/components/combobox/ax#deterministic).

## One value or several

A Combobox picks one value by default, and shows its label in the text field. With `multiple`, it picks any number, and each one becomes a tag on a row under the text, which grows onto more lines as tags wrap. The text clears after each pick, so people can search for the next one, and the panel stays open while they do.

::combobox-multiple-example
::framework-switcher

We put the tags under the text, rather than before it on the same row, since people need to see what they type as they type it, however many values they've picked. The tags come after the text in the page too, so `Tab` reaches the remove buttons in the order people read them, the way the Select's do.

## Groups and separators

Options can sit in groups, each with a heading, and a separator can go between groups or options, the same list the Select takes. As people type, a group with no match hides along with its heading, and so does a separator with nothing on one side of it, so the panel never shows an empty heading or two rules in a row.

## Icons

An option can have an icon, like a label's symbol or a country's flag, which helps people scan the suggestions and recognise what they picked. The `icon` slot gets each option, and the Combobox shows what it returns before the option's label in the panel, before the text while it shows the picked option's label and in each tag, the way the [Select](/docs/components/select/ui#icons) does, so a picked value looks the same in both.

::combobox-icons-example
::framework-switcher
#react
```tsx
const icons = { bug: BugIcon, feature: SparklesIcon, docs: BookOpenIcon, question: CircleHelpIcon };

<Field label="Labels">
  <Combobox id="labels" name="labels" multiple options={labels} placeholder="Type a label"
    icon={({ option }) => {
      const Icon = icons[option.value];
      return <Icon />;
    }}
  />
</Field>
```

#vue
```vue
<Field label="Labels">
  <Combobox id="labels" name="labels" multiple :options="labels" placeholder="Type a label">
    <template #icon="{ option }"><component :is="icons[option.value]" /></template>
  </Combobox>
</Field>
```

#svelte
```svelte
<Field label="Labels">
  <Combobox id="labels" name="labels" multiple options={labels} placeholder="Type a label">
    {#snippet icon({ option })}
      {@const Icon = icons[option.value]}
      <Icon />
    {/snippet}
  </Combobox>
</Field>
```

#angular
```angular-html
<div appField label="Labels">
  <div appCombobox multiple [options]="labels" placeholder="Type a label">
    <select id="labels" name="labels"></select>
    <ng-template appComboboxIcon let-option="option"><lucide-icon [name]="icons[option.value]" /></ng-template>
  </div>
</div>
```

#solid
```tsx
const icons = { bug: BugIcon, feature: SparklesIcon, docs: BookOpenIcon, question: CircleHelpIcon };

<Field label="Labels">
  <Combobox id="labels" name="labels" multiple options={labels} placeholder="Type a label"

  />
</Field>
```

#astro
```astro

  <Combobox id="labels" name="labels" multiple options={labels} placeholder="Type a label">
    <Fragment slot="icon">{({ option }) => { const Icon = icons[option.value]; return <Icon />; }}</Fragment>
  </Combobox>
</Field>
```

#vanilla
```html

<div id="labels-option-0" data-slot="option" role="option" aria-selected="true">
  <span data-slot="icon" aria-hidden="true"><svg class="lucide-bug">…</svg></span>
  <span data-slot="option-label">Bug</span>
  <svg data-slot="check" aria-hidden="true">…</svg>
</div>
```
::
::

Icons are decoration, so they're hidden from assistive technologies, and the label alone names each option ([WCAG 1.1.1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html)). Keep it that way, since an icon that means something the label doesn't say is lost on anyone who can't see it. Once people type, the text no longer names the picked option, so its icon leaves the field until the text shows its label again, and text people kept with `allowCustomValue` has no option, so it has no icon. The icon comes through a slot rather than a field in `options`, so it works with whatever icon library you use, and the options stay plain data you can send from a server.

## Sizes

There are five sizes, `xs`, `sm`, `md`, `lg` and `xl`, the same as the [Input](/docs/components/input/ui#sizes) and the [Select](/docs/components/select/ui#sizes), so a combobox lines up with them and with a [Button](/docs/components/button/ui#sizes) in a row. The size also sets the panel's text and the tags' height, so they match the field they come from.

## States

The field has the Input's states, and the options have the Select's:

- **Hover**, on pointers that can hover, darkens the border, and an option under the pointer gets a background.
- **Focus** draws a ring around the whole field while the text has focus, and the **highlighted** option, the one the arrow keys moved to, gets a 2px outline of the same colour, since focus stays in the text.
- **Open** turns the chevron.
- **Disabled** dims the field to 50%, and leaves it out of the form.
- **Read-only** draws a dashed border, keeps the value and its contrast, and doesn't open.
- **Invalid** draws a second pixel of border in the error colour, while the Field shows the message.
- A **selected** option is bolder and has a check mark, so it never rests on one cue, and a **disabled** option is at 50%.

The focus ring and the highlight take the theme's `--color--focus`, the same as every other component's focus, so they change with your theme rather than with a variable of the Combobox's. ## Tokens

The Combobox reads the Select's variables for every part the two draw alike: the field, its sizes, the panel, the options, the group labels, the separators and the tags. So a class that sets `--select--option--radius` rounds the options of both, and there's one place to change how a listbox looks across your product. That's what the Design Tokens page's [`tokens/component-scope`](/docs/foundations/design-tokens#checklist) allows for parts a component shares, and the contract lists them under `shared`.

| Part   | Shared tokens, from the Select                                                                                        |
| ------ | --------------------------------------------------------------------------------------------------------------------- |
| Field  | `--select--height`, `--select--padding`, `--select--gap`, `--select--font-size`, `--select--radius`, `--select--border-color`, `--select--background`, `--select--icon--size`, `--select--leading--color`, `--select--value--placeholder-color` |
| Arrow  | `--select--arrow--size`, `--select--arrow--color`                                                                     |
| Panel  | `--select--panel--offset`, `--select--panel--padding`, `--select--panel--max-height`, `--select--panel--radius`, `--select--panel--border-color`, `--select--panel--background`, `--select--panel--box-shadow` |
| Option | `--select--option--padding-block`, `--select--option--padding-inline`, `--select--option--radius`, `--select--option--color`, `--select--option--hover--background`, `--select--option--selected--background`, `--select--option--selected--font-weight`, `--select--option--disabled--opacity` |
| Tag    | `--select--tag--height`, `--select--tag--padding`, `--select--tag--radius`, `--select--tag--font-size`, `--select--tag--background`, `--select--tag--color`, `--select--tag--icon--size` |
| Group label | `--select--group-label--padding-block`, `--select--group-label--padding-inline`, `--select--group-label--font-size`, `--select--group-label--font-weight`, `--select--group-label--color` |
| Separator | `--select--separator--color`, `--select--separator--margin`                                                        |

The Combobox has variables of its own only for what the Select doesn't draw, the "No results" text:

| Token                              | What it styles                                                        |
| ---------------------------------- | --------------------------------------------------------------------- |
| `--combobox--empty--padding-block` | The space above and below "No results"                                |
| `--combobox--empty--padding-inline` | The space before and after it, the options' own                      |
| `--combobox--empty--color`         | Its colour, the text colour at 70%, which has 4.5:1 like a placeholder |

Here's one class, on a Combobox and on a Select, that restyles the field, the panel, the options and the tags of both:

Set the variables from a class of yours, never with an inline style, since the components' styles sit in the `components` cascade layer, and a class outside it wins without a fight. The [Design Tokens](/docs/foundations/design-tokens) page explains why.

The sections below restyle each part on its own, with its variables and, where it has one, its slot. The leading icon restyles with the field, and the option icons have [their own section](/docs/components/combobox/ui#icons).

## UI Checklist

| Rule                         | Level  | Scope     | Requirement | Basis | Check |
| ---------------------------- | ------ | --------- | ----------- | ----- | ----- |
| `combobox/visible-focus`     | Must   | Component | The field shows a focus ring while its text has focus, and the highlighted option an outline at least 2px thick | WCAG 2.4.7 (AA) | Keyboard, Visual regression test |
| `combobox/selected-not-colour` | Must | Component | A picked option shows a check mark as well as its weight, and its tag, with `multiple` | WCAG 1.4.1 (A) | Visual regression test |
| `combobox/contrast`          | Must   | Both      | The text, the placeholder and "No results" have 4.5:1, and the border, the chevron and the focus ring 3:1, in light and dark mode | WCAG 1.4.3, 1.4.11 (AA) | Contrast checker |
| `combobox/target-size`       | Must   | Component | The toggle and each remove button are at least 24 × 24px to press, and 44px tall where a pointer is coarse, like the options | Open Components, beyond WCAG 2.5.8 (AA) | Emulation, Review |
| `combobox/shared-tokens`     | Should | Component | The field, the panel, the options, the group labels, the separators and the tags read the Select's variables, so one class restyles both | Open Components | Review |
| `combobox/sizes`             | Should | Component | Its five sizes are the Input's and the Select's, and the panel's text and the tags follow the field's size | Open Components | Visual regression test |
| `combobox/text-size-touch`   | Must   | Component | Its text is at least 16px where any pointer is coarse, so Safari doesn't zoom in on focus | Open Components | Emulation |
| `combobox/no-layout-shift`   | Must   | Component | Opening the panel, filtering and picking move nothing else on the page | Open Components | Visual regression test |

## FAQ

::accordion
:::accordion-item{label="Why does it share the Select's tokens rather than have its own?"}
Because they're the same parts. A Combobox and a Select often sit in one form, and people should recognise the panel and its options as the same thing in both. With two sets of variables, the two drift apart the first time someone restyles one and forgets the other. With one, a class restyles both, and the contract says which variables each one shares under `shared`.
:::

:::accordion-item{label="Why aren't the tags inside the text, like chips?"}
Chips before the text push it to the end of the last row, so it gets narrower with every value, and screen reader and keyboard users meet every tag's remove button before they reach the text. Under the text, people always see what they type, and `Tab` goes from the text to the tags, in the order people read them. If you'd like them on the same row, you can lay them out that way from the shared styles, as long as the order in the page follows what people see.
:::
::
