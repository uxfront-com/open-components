Let's start with how a combobox looks: its parts, one or several values, groups, sizes, its states and the variables that restyle each part.

## Anatomy

::combobox-anatomy
1. **Field** — The root, a `<div>` that draws the border, the background and the focus ring, and holds the parts below.
2. **Leading icon** — Optional. An icon before the text, hidden from assistive technologies.
3. **Text** — The `<input>` people type in, which has the `combobox` role and shows the picked option's label.
4. **Toggle** — A `<button>` with the chevron, which opens and closes the panel and turns as it does. It's out of the tab order.
5. **Tag** — With `multiple`, one per value, with its own remove button, on a row under the text.
6. **Panel** — The floating listbox, with its own scroll boundary, in the top layer while it's open.
7. **Group label** — Optional. A heading for a group of options.
8. **Option** — One suggestion, with its hover, highlighted, selected and disabled states, and a check mark when it's picked.
9. **Separator** — Optional. A rule between options or groups.
10. **Create option** — With `creatable`, a last option that adds what people typed. In its place, the panel says "No results" when nothing matches.
::

The field is the root, as on the [Select](/docs/components/select/ui#anatomy), and the `<input>` fills its first row, under the icons, so it lines up with an [Input](/docs/components/input/ui#anatomy) of the same size. The panel, its options, its groups, its separators and the tags are the Select's, drawn by the same code with the same tokens, so the two components look the same wherever they meet. You can see the order of the parts in the [DOM contract](/docs/components/combobox/ax#deterministic).

## One value or several

A Combobox picks one value by default, and shows its label in the text field. With `multiple`, it picks any number, and each one becomes a tag on a row under the text, which grows onto more lines as tags wrap. The text clears after each pick, so people can search for the next one, and the panel stays open while they do.

We put the tags under the text, rather than before it on the same row, since people need to see what they type as they type it, however many values they've picked. The tags come after the text in the page too, so `Tab` reaches the remove buttons in the order people read them, the way the Select's do.

## Groups and separators

Options can sit in groups, each with a heading, and a separator can go between groups or options, the same list the Select takes. As people type, a group with no match hides along with its heading, and so does a separator with nothing on one side of it, so the panel never shows an empty heading or two rules in a row.

## Sizes

There are five sizes, `xs`, `sm`, `md`, `lg` and `xl`, the same as the [Input](/docs/components/input/ui#sizes) and the [Select](/docs/components/select/ui#sizes), so a combobox lines up with them and with a [Button](/docs/components/button/ui#sizes) in a row. ## States

The field has the Input's states, and the options have the Select's:

- **Hover**, on pointers that can hover, darkens the border, and an option under the pointer gets a background.
- **Focus** draws a ring around the whole field while the text has focus, and the **highlighted** option, the one the arrow keys moved to, gets a 2px outline of the same colour, since focus stays in the text.
- **Open** turns the chevron.
- **Disabled** dims the field to 50%, and leaves it out of the form.
- **Read-only** draws a dashed border, keeps the value and its contrast, and doesn't open.
- **Invalid** draws a second pixel of border in the error colour, while the Field shows the message.
- A **selected** option is bolder and has a check mark, so it never rests on one cue, and a **disabled** option is at 50%.

## Tokens

The Combobox reads the Select's variables for every part the two draw alike: the field, its sizes, the panel, the options, the group labels, the separators and the tags. So a class that sets `--select--option--radius` rounds the options of both, and there's one place to change how a listbox looks across your product. That's what the Design Tokens page's [`tokens/component-scope`](/docs/foundations/design-tokens#checklist) allows for parts a component shares, and the contract lists them under `shared`.

| Part   | Shared tokens, from the Select                                                                                        |
| ------ | --------------------------------------------------------------------------------------------------------------------- |
| Field  | `--select--height`, `--select--padding`, `--select--gap`, `--select--font-size`, `--select--radius`, `--select--border-color`, `--select--background`, `--select--icon--size`, `--select--leading--color`, `--select--value--placeholder-color` |
| Arrow  | `--select--arrow--size`, `--select--arrow--color`                                                                     |
| Panel  | `--select--panel--offset`, `--select--panel--padding`, `--select--panel--max-height`, `--select--panel--radius`, `--select--panel--border-color`, `--select--panel--background`, `--select--panel--box-shadow` |
| Option | `--select--option--padding-block`, `--select--option--padding-inline`, `--select--option--radius`, `--select--option--color`, `--select--option--hover--background`, `--select--option--selected--background`, `--select--option--selected--font-weight`, `--select--option--disabled--opacity` |
| Tag    | `--select--tag--height`, `--select--tag--padding`, `--select--tag--radius`, `--select--tag--font-size`, `--select--tag--background`, `--select--tag--color`, `--select--tag--icon--size` |
| Group label | `--select--group-label--padding-block`, `--select--group-label--padding-inline`, `--select--group-label--font-size`, `--select--group-label--font-weight`, `--select--group-label--color` |
| Separator | `--select--separator--color`, `--select--separator--margin`                                                        |

The Combobox has variables of its own only for what the Select doesn't draw, the "No results" text:

| Token                              | What it styles                                                        |
| ---------------------------------- | --------------------------------------------------------------------- |
| `--combobox--empty--padding-block` | The space above and below "No results"                                |
| `--combobox--empty--padding-inline` | The space before and after it, the options' own                      |
| `--combobox--empty--color`         | Its colour, the text colour at 70%, which has 4.5:1 like a placeholder |

## FAQ

### Why does it share the Select's tokens rather than have its own?

Because they're the same parts. A Combobox and a Select often sit in one form, and people should recognise the panel and its options as the same thing in both. With two sets of variables, the two drift apart the first time someone restyles one and forgets the other. With one, a class restyles both, and the contract says which variables each one shares under `shared`.

### Why aren't the tags inside the text, like chips?

Chips before the text push it to the end of the last row, so it gets narrower with every value, and screen reader and keyboard users meet every tag's remove button before they reach the text. Under the text, people always see what they type, and `Tab` goes from the text to the tags, in the order people read them. If you'd like them on the same row, you can lay them out that way from the shared styles, as long as the order in the page follows what people see.
