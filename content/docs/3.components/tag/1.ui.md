Let's start with how a tag looks: its parts, its sizes, its icon, how it shows its states and the variables that restyle each part.

## Anatomy

::tag-anatomy
1. **Container** — The root, a `<span>`, which draws the background and holds the parts.
2. **Leading icon** — Optional. An icon before the label, hidden from assistive technologies.
3. **Label** — The text, which holds the link when the tag is one.
4. **Remove button** — Optional. A `<button>` after the label, named after it, like "Remove Bug".
5. **Focus ring** — An outline around the whole tag when its link has focus, drawn outside it so nothing moves.
::

Every tag has a container and a label. The leading icon renders when you give it one, and the remove button when the tag is `removable`, as long as it's neither disabled nor read-only. The link and the remove button sit side by side, never one inside the other, since HTML doesn't allow a button inside a link (see [Don't nest interactive elements](/docs/components/tag/ux#dont-nest-interactive-elements)). You can see the order of the parts in the [DOM contract](/docs/components/tag/ax#deterministic).

## Sizes

A Tag has the [Input](/docs/components/input/ui#sizes)'s five size names, and at each one it's as tall as the [Select](/docs/components/select/ui#sizes)'s tags at that size, so a tag on its own looks the same as one in a Select. We recommend `size` over setting a height, since it scales the text and the remove button together.

::tag-sizes-example
::framework-switcher
#react
```tsx
<Tag size="xs" label="Bug" removable onRemove={remove} />
<Tag size="sm" label="Bug" removable onRemove={remove} />
{/* …md, lg and xl */}
```

#vue
```vue
<Tag size="xs" label="Bug" removable @remove="remove" />
<Tag size="sm" label="Bug" removable @remove="remove" />
<!-- …md, lg and xl -->
```

#svelte
```svelte
<Tag size="xs" label="Bug" removable onremove={remove} />
<Tag size="sm" label="Bug" removable onremove={remove} />
<!-- …md, lg and xl -->
```

#angular
```angular-html
<span appTag size="xs" label="Bug" removable (remove)="remove()"></span>
<span appTag size="sm" label="Bug" removable (remove)="remove()"></span>
<!-- …md, lg and xl -->
```

#solid
```tsx
<Tag size="xs" label="Bug" removable onRemove={remove} />
<Tag size="sm" label="Bug" removable onRemove={remove} />
{/* …md, lg and xl */}
```

#astro
```astro

<Tag size="sm" label="Bug" removable />
<!-- …md, lg and xl. A script listens for clicks on the remove buttons. -->
```

#vanilla
```html
<span class="tag" data-size="xs">
  <span data-slot="label">Bug</span>
  <button data-slot="remove" type="button" aria-label="Remove Bug">…</button>
</span>
<span class="tag" data-size="sm">
  <span data-slot="label">Bug</span>
  <button data-slot="remove" type="button" aria-label="Remove Bug">…</button>
</span>
<!-- …md, lg and xl -->
```
::
::

| Size | Height | Font size | Padding |
| ---- | ------ | --------- | ------- |
| `xs` | 18px   | 11px      | 4px     |
| `sm` | 20px   | 12px      | 8px     |
| `md` | 24px   | 12px      | 8px     |
| `lg` | 28px   | 14px      | 8px     |
| `xl` | 32px   | 14px      | 8px     |

Heights are minimums, so a tag grows with larger text rather than clipping it. The remove button is as wide as the tag is tall, and at every size it takes a press over at least 24 × 24px, which [Contrast and size](/docs/components/tag/ux#contrast-and-size) explains.

## Icons

A tag can have an icon before its label, like a label's symbol on an issue, which helps people scan a row of tags. The `leading` slot takes it, and the Tag sizes it to the text with `--tag--icon--size`.

::tag-icons-example
::framework-switcher
#react
```tsx
<Tag label="Bug" leading={<BugIcon />} />
<Tag label="Feature" leading={<SparklesIcon />} />
<Tag label="Docs" leading={<BookOpenIcon />} />
```

#vue
```vue
<Tag label="Bug"><template #leading><BugIcon /></template></Tag>
<Tag label="Feature"><template #leading><SparklesIcon /></template></Tag>
<Tag label="Docs"><template #leading><BookOpenIcon /></template></Tag>
```

#svelte
```svelte
<Tag label="Bug">{#snippet leading()}<BugIcon />{/snippet}</Tag>
<Tag label="Feature">{#snippet leading()}<SparklesIcon />{/snippet}</Tag>
<Tag label="Docs">{#snippet leading()}<BookOpenIcon />{/snippet}</Tag>
```

#angular
```angular-html
<span appTag label="Bug"><lucide-icon leading name="bug" /></span>
<span appTag label="Feature"><lucide-icon leading name="sparkles" /></span>
<span appTag label="Docs"><lucide-icon leading name="book-open" /></span>
```

#solid
```tsx
<Tag label="Bug" leading={<BugIcon />} />
<Tag label="Feature" leading={<SparklesIcon />} />
<Tag label="Docs" leading={<BookOpenIcon />} />
```

#astro
```astro
<Tag label="Bug"><BugIcon slot="leading" /></Tag>
<Tag label="Feature"><SparklesIcon slot="leading" /></Tag>
<Tag label="Docs"><BookOpenIcon slot="leading" /></Tag>
```

#vanilla
```html
<span class="tag" data-size="md">
  <span data-slot="leading" aria-hidden="true"><svg class="lucide-bug">…</svg></span>
  <span data-slot="label">Bug</span>
</span>
```
::
::

Icons are decoration, so they're hidden from assistive technologies, and the label alone names the tag ([WCAG 1.1.1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html)). Keep it that way, since an icon that means something the label doesn't say is lost on anyone who can't see it. The Select's tags take their icon through a slot called `icon`, because it's the option's icon there, shown in the panel too. On its own, the Tag calls it `leading`, like the Button and the Input.

## States

A plain tag has no states, since there's nothing to do with it. A tag that's a link, or that's removable, has hover and focus on the parts people press, and any tag can be disabled or read-only.

::tag-states-example
::framework-switcher
#react
```tsx
<Tag label="Bug" />
<Tag label="Bug" href="/labels/bug" />
<Tag label="Bug" removable onRemove={remove} />
<Tag label="Bug" href="/labels/bug" removable disabled />
<Tag label="Bug" href="/labels/bug" removable readonly />
```

#vue
```vue
<Tag label="Bug" />
<Tag label="Bug" href="/labels/bug" />
<Tag label="Bug" removable @remove="remove" />
<Tag label="Bug" href="/labels/bug" removable disabled />
<Tag label="Bug" href="/labels/bug" removable readonly />
```

#svelte
```svelte
<Tag label="Bug" />
<Tag label="Bug" href="/labels/bug" />
<Tag label="Bug" removable onremove={remove} />
<Tag label="Bug" href="/labels/bug" removable disabled />
<Tag label="Bug" href="/labels/bug" removable readonly />
```

#angular
```angular-html
<span appTag label="Bug"></span>
<span appTag label="Bug" [href]="'/labels/bug'"></span>
<span appTag label="Bug" removable (remove)="remove()"></span>
<span appTag label="Bug" [href]="'/labels/bug'" removable disabled></span>
<span appTag label="Bug" [href]="'/labels/bug'" removable readonly></span>
```

#solid
```tsx

<Tag label="Bug" href="/labels/bug" />
<Tag label="Bug" removable onRemove={remove} />
<Tag label="Bug" href="/labels/bug" removable disabled />
<Tag label="Bug" href="/labels/bug" removable readonly />
```

#astro
```astro

<Tag label="Bug" href="/labels/bug" />
<Tag label="Bug" removable />
<Tag label="Bug" href="/labels/bug" removable disabled />
<Tag label="Bug" href="/labels/bug" removable readonly />
```

#vanilla
```html
<span class="tag" data-size="md"><span data-slot="label">Bug</span></span>

<span class="tag" data-size="md"><span data-slot="label"><a href="/labels/bug">Bug</a></span></span>

<span class="tag" data-size="md">
  <span data-slot="label">Bug</span>
  <button data-slot="remove" type="button" aria-label="Remove Bug">…</button>
</span>

<span class="tag" data-size="md" data-disabled>
  <span data-slot="label"><a role="link" aria-disabled="true">Bug</a></span>
</span>

<span class="tag" data-size="md" data-readonly>
  <span data-slot="label"><a href="/labels/bug">Bug</a></span>
</span>
```
::
::

| State     | Selector                                                     | Recommended look                                                     |
| --------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| Link      | `:has(> [data-slot=label] a)` on the root                    | A border at 55% of the text colour, which a plain tag doesn't have   |
| Hover     | `a[href]:hover` or `[data-slot=remove]:hover`, inside `@media (hover: hover)` | On a link, the background at 16% of the text colour, up from 10%, and the label underlined. On the remove button, the same background behind it |
| Focus     | `a:focus-visible::after`, and `[data-slot=remove]:focus-visible` | A 2px outline in `--color--focus`, 2px outside the tag for its link, and inside the remove button's edge |
| Disabled  | `[data-disabled]`                                            | The whole tag at 50% opacity, without its remove button              |
| Read-only | `[data-readonly]`                                            | The tag's usual look, without its remove button                      |

A link tag has a border, so people can tell it from a plain tag without relying on its colour, which colour blind people may not see ([WCAG 1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)). The border is drawn inside the tag, so a link tag is the same size as a plain one, and as the Select's tags. None of the states change the tag's size or position, so a row of tags doesn't shift as the pointer moves along it, and you'll find how they behave under [Every state](/docs/components/tag/ux#every-state).

## Tokens

The Tag's look comes from variables on its root, which you can set from a class. Tokens are named as token paths: `--tag--…` for the tag, then a group per part or state, like `--tag--icon--…` and `--tag--link--…`. They're in the `components` layer, so a class of yours wins without any specificity tricks.

| Token                                          | Default                                     | Part               |
| ---------------------------------------------- | ------------------------------------------- | ------------------ |
| `--tag--height`                                | `1.5rem`, per size                          | Container          |
| `--tag--padding`                               | `0.5rem`, per size                          | Container          |
| `--tag--gap`                                   | `0.25rem`                                   | Leading icon       |
| `--tag--radius`                                | `0.25rem`                                   | Container          |
| `--tag--font-size`                             | `0.75rem`, per size                         | Label              |
| `--tag--background`                            | The text colour at 10%                      | Container          |
| `--tag--color`                                 | `--color--neutral-text`                     | Label              |
| `--tag--border-color`                          | `transparent`                               | Container          |
| `--tag--icon--size`                            | `1em`                                       | Leading icon       |
| `--tag--link--border-color`                    | The text colour at 55%                      | Container, as a link |
| `--tag--hover--background`                     | The text colour at 16%                      | Link and remove button, on hover |

It reads `--color--neutral-text` and `--color--focus` from your theme. A Tag at a size has the same height, padding, radius and font size as the Select's tags at that size, and each of their tokens has a Tag token with the same job. The one default that differs is the text colour: a Select's tag inherits it from the field, while a Tag sets `--color--neutral-text` itself, since it isn't inside one.

| The Select's token            | The Tag's token        |
| ----------------------------- | ---------------------- |
| `--select--tag--height`       | `--tag--height`        |
| `--select--tag--padding`      | `--tag--padding`       |
| `--select--tag--radius`       | `--tag--radius`        |
| `--select--tag--font-size`    | `--tag--font-size`     |
| `--select--tag--background`   | `--tag--background`    |
| `--select--tag--color`        | `--tag--color`         |
| `--select--tag--icon--size`   | `--tag--icon--size`    |

The label has a contrast of at least 4.5:1 against the tag's background, which is the text colour at 10% over the page. With our reference tokens, from the Tailwind CSS palette, that's 12.3:1 on white and 10.9:1 on zinc-900. A link tag's border is the text colour at 55%, like the Input's, which comes to 3.5:1 against white and 5:1 against zinc-900, so people can see it's there ([WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)). The sections below restyle the tag's three parts, each with its variables and, where it has one, its slot.

### Container and label

The root draws the tag, so its tokens set the background, the text colour and the radius. The default slot changes what the label says, and the remove button keeps its name, which comes from `label`.

::tag-restyle-example{part="root"}
::framework-switcher
#react
```tsx
<Tag className="brand" label="Bug" removable onRemove={remove} />
```

```css
  --tag--radius: 1rem;
  --tag--background: var(--color--primary);
  --tag--color: var(--color--primary-contrast);
```

## UI Checklist

| Rule                   | Level  | Scope     | Requirement | Basis | Check |
| ---------------------- | ------ | --------- | ----------- | ----- | ----- |
| `tag/sizes`            | Should | Component | It takes the Input's five size names, each as tall as the Select's tag at that size | Open Components | Unit test, Visual regression test |
| `tag/target-size`      | Must   | Component | The remove button and a link label each take a press over at least 24 × 24px, and at least 44px tall on a touch screen | WCAG 2.5.8 (AA), 2.5.5 (AAA) | Emulation |
| `tag/contrast`         | Must   | Both      | The label has at least 4.5:1 against the tag's background, and the focus ring at least 3:1 against what's behind it | WCAG 1.4.3, 1.4.11 (AA) | Contrast checker |
| `tag/focus-visible`    | Must   | Component | The link and the remove button show an outline at least 2px thick on `:focus-visible` | WCAG 2.4.7 (AA) | Keyboard |
| `tag/resizable`        | Must   | Component | The tag is sized with a `min-height` in `rem`, so it grows with its text | Open Components, beyond WCAG 1.4.4 (AA) | 200% zoom |
| `tag/decorative-icons` | Must   | Component | The leading icon and the remove button's icon are hidden from assistive technologies | WCAG 1.1.1 (A) | Unit test, ARIA snapshot |
| `tag/link-distinct`    | Should | Component | A link tag looks different from a plain one by more than its colour, like a border | Open Components, beyond WCAG 1.4.1 (A) | Visual regression test |
| `tag/truncate`         | Should | Component | A long label stays on one line and ends in an ellipsis, while its full text stays in the DOM | Open Components | Unit test, Visual regression test |
| `tag/stable-size`      | Should | Component | Hover, focus and being a link don't change the tag's size or position | Open Components | Visual regression test |
| `tag/tokens`           | Must   | Component | Each part sets its look through `--tag--…` token paths in the `components` layer | Open Components | Stylelint |
| `tag/forced-colors`    | Must   | Component | The tag's boundary, its focus ring and its disabled state stay visible in forced colours mode | Open Components | Emulation |

## FAQ

::accordion
:::accordion-item{label="Why doesn't the Tag have a color prop?"}
Because a colour that means something, like red for an error, is a status, and a status is the Badge's job. Tags that are coloured by category, like the labels on an issue, get their colours from your data rather than from a fixed set, so they're better set from a class, as [Container and label](/docs/components/tag/ui#container-and-label) shows. Adding a `color` later wouldn't break anything, if a design system needs one.
:::
::
