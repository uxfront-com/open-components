Let's start with how a select looks: its parts, one or several values, groups, sizes, its states and the variables that restyle each part.

## Anatomy

::select-anatomy
1. **Trigger** — The field itself, a `<div>` that draws the border, the background and the focus ring, and holds the parts below.
2. **Leading icon** — Optional. An icon before the value, hidden from assistive technologies.
3. **Icon** — Optional. An icon for each option, shown in the panel, beside the picked value and in each chip, hidden from assistive technologies.
4. **Chip** — With `multiple`, one per value, with its own remove button. Chips sit beside the button, inside the field.
5. **Value** — The picked option's label, or the placeholder, inside the `<button>` that has the `combobox` role.
6. **Arrow** — The chevron, which turns as the panel opens, hidden from assistive technologies.
7. **Panel** — The floating listbox, with its own scroll boundary, in the top layer while it's open.
8. **Group label** — Optional. A heading for a group of options.
9. **Option** — One choice, with its hover, highlighted, selected and disabled states and a check mark when it's picked.
10. **Separator** — Optional. A rule between options or groups.
::

The trigger is the root, and it isn't the button. That's because a `<button>` [can't contain other interactive content](https://html.spec.whatwg.org/multipage/dom.html#interactive-content), and each chip holds a remove button. So the root draws the field the way the [Input](/docs/components/input/ui#anatomy)'s does, and the `<button>` fills it, under the chips and the icons, which a press goes straight through. You can see the order of the parts in the [DOM contract](/docs/components/select/ax#deterministic).

## One value or several

A Select picks one value by default, and shows its label in the field. With `multiple`, it picks any number, and each one becomes a chip in the field, which grows onto more lines as chips wrap. The panel stays open while people toggle options, since they're likely to want more than one.

::framework-switcher

```tsx
</Field>
```

::
::

Each chip holds a real `<button>` to remove it, and the control holds the values as visually hidden text, so the combobox still has a value for a screen reader to read. Past three values, it reads a count instead, since nobody wants a long list read out every time focus lands on the field.

We recommend chips over a line like "3 selected", because people can see what they picked and remove one without opening the list.

## Icons

An option can have an icon, like a label's symbol or a country's flag, which helps people scan a long list and recognise what they picked. The `icon` slot gets each option, and the Select shows what it returns before the option's label in the panel, before the value once it's picked and in each chip, so a picked value looks the same everywhere.

::select-icons-example
::framework-switcher
#react
```tsx
const icons = { bug: BugIcon, feature: SparklesIcon, docs: BookOpenIcon, question: CircleHelpIcon };

<Field label="Labels">
  <Select id="labels" name="labels" multiple options={labels} nativeOnTouch={false}
    icon={({ option }) => {
      const Icon = icons[option.value];
      return <Icon />;
    }}
  />
</Field>
```

#vue
```vue
<Field label="Labels">
  <Select id="labels" name="labels" multiple :options="labels" :native-on-touch="false">
    <template #icon="{ option }"><component :is="icons[option.value]" /></template>
  </Select>
</Field>
```

#svelte
```svelte
<Field label="Labels">
  <Select id="labels" name="labels" multiple options={labels} nativeOnTouch={false}>
    {#snippet icon({ option })}
      {@const Icon = icons[option.value]}
      <Icon />
    {/snippet}
  </Select>
</Field>
```

#angular
```angular-html
<div appField label="Labels">
  <div appSelect multiple [options]="labels" [nativeOnTouch]="false">
    <select id="labels" name="labels"></select>
    <ng-template icon let-option="option"><lucide-icon [name]="icons[option.value]" /></ng-template>
  </div>
</div>
```

#solid
```tsx
const icons = { bug: BugIcon, feature: SparklesIcon, docs: BookOpenIcon, question: CircleHelpIcon };

<Field label="Labels">
  <Select id="labels" name="labels" multiple options={labels} nativeOnTouch={false}
    icon={({ option }) => <Dynamic component={icons[option.value]} />}
  />
</Field>
```

#astro

```astro
    <Fragment slot="icon">{({ option }) => { const Icon = icons[option.value]; return <Icon />; }}</Fragment>
  </Select>
</Field>
```

#vanilla
```html

<div id="labels-option-0" data-slot="option" role="option" aria-selected="true">
  <span data-slot="icon" aria-hidden="true"><svg class="lucide-bug">…</svg></span>
  <span data-slot="option-label">Bug</span>
  <svg data-slot="check" viewBox="0 0 24 24" aria-hidden="true">…</svg>
</div>
```
::
::

Icons are decoration, so they're hidden from assistive technologies, and the label alone names each option ([WCAG 1.1.1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html)). Keep it that way, since an icon that means something the label doesn't say is lost on anyone who can't see it. The icon comes through a slot rather than a field in `options`, so it works with whatever icon library you use, and the options stay plain data you can send from a server. The native rendering draws text only, so it shows no icons.

## Sizes

A Select has the [Input](/docs/components/input/ui#sizes)'s five sizes, with the same heights and the same radius, so a Select, an Input and a Button line up in a row. Use `size` for this, rather than setting a height, since it scales the padding, the text, the arrow and the chips together.

| State        | Selector on the active control or option                 | What it looks like                                        |
| ------------ | -------------------------------------------------------- | --------------------------------------------------------- |
| Default      | none                                                     | A border at 3:1 against the page                          |
| Hover        | `:hover` on the field, where a pointer can hover         | A stronger border                                         |
| Focus        | `:focus-visible`                                         | A 2px ring around the whole field, 2px away               |
| Open         | `[data-state="open"]`                                    | The arrow turned, and the panel showing                   |
| Disabled     | `:disabled`                                              | Faded to 50%, and left out of its form                    |
| Read-only    | `[aria-readonly="true"]`                                 | A dashed border, with the value at full contrast          |
| Invalid      | `[aria-invalid="true"]`                                  | An error-coloured border, 2px wide without growing        |
| Highlighted  | `[data-active="true"]`, on an option                     | A 2px outline inside the option, as focus stays on the control |
| Selected     | `[aria-selected="true"]`, on an option                   | A heavier weight and a check mark                         |
| Disabled option | `[aria-disabled="true"]`, on an option                | Faded, and skipped by the keyboard                        |

A picked option has both a check mark and a heavier weight, so it doesn't rest on colour alone ([WCAG 1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)). Keep the field at 3:1 against the page ([WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)) and text at 4.5:1 ([WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)), which the defaults reach through `currentColor`, so a restyle has to keep them too.

The press targets are at least 24 × 24px ([WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)), the remove button included, whatever size the chip is. On a touch screen, the field, each option and each remove button reach at least 44px tall, which is [WCAG 2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)'s larger target.

## Tokens

The Select's look comes from variables on its root, which you can set from a class. Tokens are named as token paths: `--select--…` for the field, then a group per part, like `--select--panel--…`, and a state gets a group too, like `--select--option--selected--…`. They're in the `components` layer, so a class of yours wins without any specificity tricks, and they stay on the root, so the panel inherits them even in the top layer.

| Token                                     | Default                                      | Part        |
| ----------------------------------------- | -------------------------------------------- | ----------- |
| `--select--height`                        | `2.25rem`, per size                          | Trigger     |
| `--select--padding`, `--select--gap`      | `0.75rem`, `0.5rem`, per size                | Trigger     |
| `--select--font-size`                     | `0.875rem`, per size                         | Trigger     |
| `--select--radius`                        | `0.5rem`, per size                           | Trigger     |
| `--select--border-color`                  | The text colour at 55%                       | Trigger     |
| `--select--background`                    | `transparent`                                | Trigger     |
| `--select--icon--size`, `--select--leading--color` | `1rem`, the text colour at 70%      | Leading     |
| `--select--value--placeholder-color`      | The text colour at 70%                       | Value       |
| `--select--arrow--size`, `--select--arrow--color` | `1rem`, the text colour at 70%        | Arrow       |
| `--select--panel--offset`, `--select--panel--padding` | `0.25rem`                         | Panel       |
| `--select--panel--max-height`             | `16rem`                                      | Panel       |
| `--select--panel--radius`                 | `0.5rem`                                     | Panel       |
| `--select--panel--border-color`           | The text colour at 20%                       | Panel       |
| `--select--panel--background`             | `Canvas`                                     | Panel       |
| `--select--panel--box-shadow`             | The Popover's                                | Panel       |
| `--select--option--padding-block`, `--select--option--padding-inline` | `0.375rem`, `0.5rem` | Option |
| `--select--option--radius`                | `0.25rem`                                    | Option      |
| `--select--option--color`                 | `inherit`                                    | Option      |
| `--select--option--hover--background`     | The text colour at 8%                        | Option      |
| `--select--option--selected--background`, `--select--option--selected--font-weight` | `transparent`, `600` | Option |
| `--select--option--disabled--opacity`     | `0.5`                                        | Option      |
| `--select--chip--height`, `--select--chip--padding` | `1.5rem`, `0.5rem`, per size       | Chip        |
| `--select--chip--radius`, `--select--chip--font-size` | `0.25rem`, `0.75rem`             | Chip        |
| `--select--chip--background`, `--select--chip--color` | The text colour at 10%, `inherit` | Chip       |
| `--select--chip--icon--size`              | `1em`                                        | Icon, in a chip |
| `--select--group-label--padding-block`, `--select--group-label--padding-inline` | `0.375rem`, `0.5rem` | Group label |
| `--select--group-label--font-size`, `--select--group-label--font-weight` | `0.75rem`, `500` | Group label |
| `--select--group-label--color`            | The text colour at 70%                       | Group label |
| `--select--separator--color`, `--select--separator--margin` | The text colour at 20%, `0.25rem` | Separator |

It reads `--color--neutral-text`, `--color--focus` and `--color--error-text` from your theme. Where a name differs from [Styleframe's Select](https://www.styleframe.dev/docs/theme/components/select), which is the model for the seven parts, it's to match what the shipped components already call things:

| Styleframe    | Here                                   | Why                                                                                        |
| ------------- | -------------------------------------- | ------------------------------------------------------------------------------------------ |
| The trigger   | The root `.select` and its `control`   | Chips hold buttons, which can't sit inside a `<button>`, so the field and the button are apart |
| `label`       | `group-label`                          | The Field owns "label", so a heading in the list needs a name of its own                   |
| `invalid`     | `aria-invalid`                         | No shipped component has an `invalid` prop: the Input, the Field and the rest read the attribute |
| Three sizes   | The Input's five                       | So a Select lines up with an Input and a Button                                            |

Each part can be restyled on its own, with its variables and, where it has one, its slot. The native rendering honours only some of them, which [Native on touch](/docs/components/select/ux#native-on-touch) lists.

## UI Checklist

| Rule                       | Level  | Scope     | Requirement | Basis | Check |
| -------------------------- | ------ | --------- | ----------- | ----- | ----- |
| `select/sizes`             | Should | Component | It takes the Input's five sizes, with the same heights, so it lines up with an Input and a Button | Open Components | Unit test, Visual regression test |
| `select/target-size`       | Must   | Component | The field, each option and each remove button are at least 24 × 24px, and at least 44px tall on a touch screen | WCAG 2.5.8 (AA) | Emulation |
| `select/focus-visible`     | Must   | Component | Focus shows a ring around the field, and the highlighted option an outline of its own | WCAG 2.4.7 (AA) | Keyboard |
| `select/contrast`          | Must   | Both      | Text has at least 4.5:1 and the field's border at least 3:1 against what's behind them | WCAG 1.4.3, 1.4.11 (AA) | Contrast checker |
| `select/not-colour-alone`  | Must   | Component | A selected option has a check mark and a heavier weight, not only a colour | WCAG 1.4.1 (A) | Review |
| `select/tokens`            | Must   | Component | Each of its seven parts sets its look through `--select--…` token paths in the `components` layer | Open Components | Stylelint |
| `select/decorative-icons`  | Must   | Component | Icons in the panel, the field and the chips are hidden from assistive technologies, so the label alone names each option | WCAG 1.1.1 (A) | Unit test, ARIA snapshot |
| `select/stable-size`       | Should | Component | Opening the panel, hovering and focusing don't change the field's size, and only chips can grow it | Open Components | Visual regression test |
